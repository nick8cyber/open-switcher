# ADR-001: Экран-гейты всех стирающих путей (mac)

Статус: принято 01.11.2026. Реализация: 36af30c, 86aba4a, f6db9b7, 69826de, 9f8dc52.

## Контекст

Windows-версия стирает и перечатывает текст по памяти хука (сколько клавиш
видело — столько стирает). Это безопасно там, потому что WH_KEYBOARD_LL —
синхронный: каждый ключ учтён, память не расходится с полем.

macOS-тап (CGEventTap) **теряет события**: бой 23.10 23:20 — в логе буфер
движка не совпал с реально нажатыми клавишами (две клавиши в буфере, в поле
их нет); ОС может молча отключить тап по таймауту колбэка (теперь логируется
как `tap DISABLED by system`), а поле может отставать от потока ввода.
Слепые backspace-бёрсты по памяти при расхождении стирают соседние слова
насовсем: тот же бой — 4 слова («весь ui - там ui») за один Option-тап.

## Решение

**Ни один backspace-бёрст не отправляется без сверки с экраном.** Перед
стиранием движок читает через AX текст фокусного элемента и позицию
каретки (`PasswordGuard.focusedTextAndCaret`) и сверяет хвост у каретки
с тем, что собирается стереть:

- авто-конвертация и энтер-фикс — `[ретро-буква + набранное]`;
- force-flip / Option-тап — `[слово]` или `[слово+разделитель]`;
- откат по Break — `[префикс + слово + знак + хвост]` (всё, что будет
  перепечатано);
- select-left — выделение обязано равняться скопированному.

Не совпало → отказ **без инжекции** (слово остаётся как набрано,
разделитель доставляется обычным путём, юзер переворачивает руками).
Дополнительно: любой забой (`lastBsAt`) снимает доверие к точному пути
флипа; после инжекции — screen-проба (+0.4 с) с явным
`INJECTION NOT APPLIED` и плашками на слепые инжекции и не-применившиеся
замены.

## Следствия

- Стирание чужого текста в читаемых приложениях (ZCode, браузеры, TextEdit)
  невозможно по построению; расхождение превращается в отказ, видимый
  в логе с поэлементной причиной.
- AX-немые приложения (telegram, finder) — единственный слепой коридор:
  инжекция по-старому + плашка «вслепую». Точечная починка AX-чтения —
  по мере накопления боёв.
- Гейт читает main-поток с потока тапа через семафор (0.2 с, deadlock
  исключён: main никогда не ждёт тап); AX-вызовы — только на main
  (инвариант TSM-краша fa5235a).
- Гонка «гейт прочитал экран — буква доехала после» остаётся теоретически
  (окно ~мс), но упирается в порядок очереди приложения: posted-события
  доставляются после уже стоящих в очереди клавиш.
- Windows-версии это не нужно (синхронный хук); при порте — не переносить
  слепое стирание в новые кодовые пути без гейта.
