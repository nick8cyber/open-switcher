# ADR-004: Паст-режим ручного флипа + дерево решений гейтов

Статус: принято 01–05.11.2026. Реализация: 1913c30 → d5819ea → 2d2e47a (итог).
Спека: §9 (паст-режим), §5.1 (гейт-стек (а)–(г)), §17.22–23.

## Контекст

Ручной переворот слова (Option-тап) стирал слово забоями (BS×N + замена).
В Electron-полях (bb — веб-апп в Chromium) это давало детерминированную порчу:
бой 02:36 ×3 — bs=6 уничтожал 31–52 чужих символа при «правильном» гейте;
бой 17:40 — 52 символа при допуске 12/13. Экран-гейт хвоста не спасает:
поле ломается на КОММИТЕ инжекции, а не на расчёте.

## Решение

Ручной флип идёт БЕЗ ЕДИНОГО backspace — атомарной заменой выделения:
`Option+Shift+Left` (выделить слово) → сверка выделения с AX (слово ± пробелы,
устаканивание ≤400 мс) → буфер = замена → `Cmd+V` → буфер восстановлен.

### Дерево решений Option-тапа (финальное)

```
Option-тап:
├─ буфер жив (≥2 клавиш, слово не завершено)
│   └─ ПАСТ-ФЛИП отложенно (вне тап-колбэка)          [см. гонки ниже]
├─ слово завершено ≤10 с + разделитель известен
│   └─ ПАСТ-ФЛИП отложенно
├─ AX не читается ДО отправки событий
│   └─ FALLBACK-Забои: старый путь с гейтом хвоста
│       (только здесь забои допустимы)
├─ иначе (слово старое / чужое приложение / нет сепаратора)
│   └─ ЧЕСТНЫЙ ОТКАЗ (плашка «тапни снова»)
```

### Гонки, пойманные самотестами (почему исполнение — вне тап-колбэка)

Всё, что постится из тап-колбэка, доставляется приложению только ПОСЛЕ его
возврата. Флоу «выдели → проверь AX → вставь» обязан ждать эффект — значит,
исполняется на фоновой очереди. Самотесты поймали: (1) Cmd+Shift+Left
выделяет до начала строки, не слово; (2) сверка выделения внутри колбэка
читала пустоту при живом комбо; (3) гасящая стрелка + протухший AX = вставка
в начало документа. Итоговое дерево исполнения:

```
paste-flip (фоновая очередь):
├─ выделение == слово (± пробелы) → Cmd+V → БУФЕР ВОССТАНОВЛЕН → OK
└─ выделение иное/пустое → стрелка гасит → ЧЕСТНЫЙ ОТКАЗ
    (забой-путь ЗАПРЕЩЁН: после отправленных событий — только отказ)
```

## Следствия

- В bb порча текста флипом невозможна по конструкции (нет забоев).
- Единственный residual: отказ вместо переворота при лаге AX — слово
  остаётся как набрано, повторный тап после устаканивания решает.
- Знак-двойники и сепаратор: сепаратор в поле не трогается (не выделен);
  слова со знаками внутри — выделение ненадёжно → отказ.
- Windows: N/A для паст-флипа (нет Option-тапа), НО PasteConvertApps
  (ae532ea) даёт тот же выделение+вставка путь для авто-конверта
  в Chromium-полях.

## Аудит субагентом (05.11) — 8 дефектов, все закрыты (2d2e47a)

1. [P1] gap на авто-конверте отсутствовал: 0ddab0a заявлял convert×2, реально
   вошли force-flip×2 — коммит-месседж врал. Исправлено (оба convert-сайта).
2. [P1] паст-конверт (replay-hostile) съедал сепаратор и не ставил точку
   отката — Break удалял вставленное слово. Исправлено: sep досылается,
   undo-точка ставится.
3. [P2] gap-BS при пустом gapBuf не синхронизировал buf (обе ветки).
4. [P2] Option+буква в gap-ветке считалась текстом.
5. [P2] ложные страйки (юзер правит BS+ретайп) → затухание 60 с + TTL
   враждебности 10 мин.
6. [P2] settle-бюджет 1,4 с резанут до 0,3 с (риск tapDisabled).
7. [P3] hotkeys мертвы в suppress-окне (комментарий врёт) — задокументировано.
8. [P3] undoLen в паст-флипе не учитывает пробелы выделения — задокументировано.

## Правило на будущее

Каждый батч фиксов проходит аудит субагентом (read-only) ДО доставки —
аудит 05.11 окупился: нашёл «коммит-месседж врал» и 3 бага моих же защит.
Двухплатформенное правило [[commit-push-every-change]]: экран-фиксы mac-only
по природе, но каждый получает вин-эквивалент или записанную причину N/A.

## Приложение 06.11 — каретка-дефекты паст-путей (жалоба «смещается, задевает, стирает»)

Разбор логов 00:53 (bb), 02:08 (zcode), 03:02 (bb) — три корня:

- **D1 стрелка-влево на отказе**: гашение выделения голым Left бросало
  каретку в НАЧАЛО слова (02:08: −1 при пустом чтении; 03:02: −3 при
  выделении «да »). Печать юзера втыкалась в чужое место. Фикс: Right
  (конец выделения = исходная каретка); пустое чтение = выделения нет =
  не слать ничего; nil (AX молчит) = Right вслепую (цена +1 < съеденное
  слово). Вин-паритет: SelDeselectOurs (VK_RIGHT) на всех отказах sel-флоу,
  только для выделений движка — выделение юзера не трогаем.
- **D2 выделение против печати**: Option+Shift+Left открывался +60 мс после
  конверта и жил до 460 мс; удар юзера в окне ЗАМЕЩАЛ выделение — слово
  стиралось (02:08: `''nj'` стёрто ударом 'x', screen-after это доказал).
  Фикс: inputSeq-счётчик нажатий (keyDown/mouseDown — БЕЗ keyUp: отпускание
  триггера прибывает в первые ~30-100 мс и ложно рвёт гвард — поймано
  аудитом 06.11 как P1), проверка до поста и в цикле; расхождение = ноль
  клавиш в ответ. Окно сокращено: ретраи только по пустому чтению.
- **D4 сепаратор**: проглоченный пробел не возвращался на отказе — слова
  склеивались. Фикс: досыл на отказе (кроме живой печати — двойной пробел
  хуже). Вин: _selResendVk чистится в BeginFixSelection (stale-утечка) и
  SendKey(vk, false, shift) — 2-арг overload принимал Shift за extended.

Десинк-детект: выделение == целевому слову («да » при цели «да») = на
экране уже правильно (память движка разошлась с системой) — честный
пропуск без переворота. 03:02 был именно этим: поле УЖЕ содержало «да »,
юбка конверта была не нужна, вред нанесён только стрелкой.

Аудит 06.11 (второй цикл): 2×P1 в первых версиях фиксов — break по
typing-abort проваливался в отказный guard (шёл Right+sep в живую печать)
и keyUp-бамп убивал паст-путь на каждом конверте. Оба закрыты до пуша.
Живое подтверждение: 04:34 bb — seq-гвард отработал («paste-abort … не
делаю»), ни одной клавиши не постнуто, каретка не тронута.

## Приложение 08.11 — вин-паритет гварда «юзер печатает» + дыра CI

Проверка «всё ли для Windows» дала три вещи:

- **Вин-эквивалент seq-гварда**: хук считает тик последнего РЕАЛЬНОГО
  keyDown (treatAsReal, без модификаторов — тот же урок про keyUp, что
  поймал аудит 06.11 на маке). BeginFixSelection снимает тик триггера
  (уже учтён хуком ДО диспетчеризации OnKeyDown), SelPollTick сверяет
  перед вставкой: расхождение = юзер печатает = НИ вставки, НИ гашения,
  НИ сепаратора (его удар уже заменил выделение, каретка его). Тот же
  гвард выключает deselect/sep на отказах. Наши инжекции не считают —
  LLKHF_INJECTED + SelfInjectDepth.
- **build.cmd глотал провал самотеста**: `exit /b 0` безусловно после
  запуска selftest — FAIL-чеки (включая +8 beta16) доезжали до релиза
  молча. Теперь `if errorlevel 1 → SELFTEST FAILED + exit /b 1`.
- **Мак, остаточные окна**: typing-чек добавлен в отказные ветки
  (hostile guard-else, runPasteFlip×2) — раньше гвард стоял только на
  входе и в retry-цикле, отказ мог отправить Right/sep в живую печать
  через ~30-80 мс после последнего чека.

Десинк-детект на вин отдельного порта НЕ требует: скопированный текст
ЕСТЬ правда поля — если память разошлась с системой, сверка
SelMatchesExpect отказывает (на маке для этого нужен AX-чек, на вине
он получается сам). Правило [[mac-port-project]]: не портировать
mac-обходы туда, где причина не существует.
