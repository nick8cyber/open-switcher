# ADR-004: Паст-режим ручного флипа + дерево решений гейтов

Статус: принято 01–05.11.2026. Реализация: 1913c30 → d5819ea → 2d2e47a (итог).
Спека: §9 (паст-режим), §5.1 (гейт-стек (а)–(г)), §17.22–23.

## Контекст

Ручной переворот слова (Option-тап) стирал слово забоями (BS×N + замена).
В Electron-полях (bb — веб-апп в Chromium) это давало детерминированную порчу:
бой 02:36 ×3 — bs=6 уничтожал 31–52 чужих символа при «правильном» гейте;
бой 17:40 — 52 символа при допуске 12/13. Экран-гейт хвоста не спасает:
поле ломается на КОММИТЕ инжекции, а не на расчёте.

## Решение

Ручной флип идёт БЕЗ ЕДИНОГО backspace — атомарной заменой выделения:
`Option+Shift+Left` (выделить слово) → сверка выделения с AX (слово ± пробелы,
устаканивание ≤400 мс) → буфер = замена → `Cmd+V` → буфер восстановлен.

### Дерево решений Option-тапа (финальное)

```
Option-тап:
├─ буфер жив (≥2 клавиш, слово не завершено)
│   └─ ПАСТ-ФЛИП отложенно (вне тап-колбэка)          [см. гонки ниже]
├─ слово завершено ≤10 с + разделитель известен
│   └─ ПАСТ-ФЛИП отложенно
├─ AX не читается ДО отправки событий
│   └─ FALLBACK-Забои: старый путь с гейтом хвоста
│       (только здесь забои допустимы)
├─ иначе (слово старое / чужое приложение / нет сепаратора)
│   └─ ЧЕСТНЫЙ ОТКАЗ (плашка «тапни снова»)
```

### Гонки, пойманные самотестами (почему исполнение — вне тап-колбэка)

Всё, что постится из тап-колбэка, доставляется приложению только ПОСЛЕ его
возврата. Флоу «выдели → проверь AX → вставь» обязан ждать эффект — значит,
исполняется на фоновой очереди. Самотесты поймали: (1) Cmd+Shift+Left
выделяет до начала строки, не слово; (2) сверка выделения внутри колбэка
читала пустоту при живом комбо; (3) гасящая стрелка + протухший AX = вставка
в начало документа. Итоговое дерево исполнения:

```
paste-flip (фоновая очередь):
├─ выделение == слово (± пробелы) → Cmd+V → БУФЕР ВОССТАНОВЛЕН → OK
└─ выделение иное/пустое → стрелка гасит → ЧЕСТНЫЙ ОТКАЗ
    (забой-путь ЗАПРЕЩЁН: после отправленных событий — только отказ)
```

## Следствия

- В bb порча текста флипом невозможна по конструкции (нет забоев).
- Единственный residual: отказ вместо переворота при лаге AX — слово
  остаётся как набрано, повторный тап после устаканивания решает.
- Знак-двойники и сепаратор: сепаратор в поле не трогается (не выделен);
  слова со знаками внутри — выделение ненадёжно → отказ.
- Windows: N/A для паст-флипа (нет Option-тапа), НО PasteConvertApps
  (ae532ea) даёт тот же выделение+вставка путь для авто-конверта
  в Chromium-полях.

## Аудит субагентом (05.11) — 8 дефектов, все закрыты (2d2e47a)

1. [P1] gap на авто-конверте отсутствовал: 0ddab0a заявлял convert×2, реально
   вошли force-flip×2 — коммит-месседж врал. Исправлено (оба convert-сайта).
2. [P1] паст-конверт (replay-hostile) съедал сепаратор и не ставил точку
   отката — Break удалял вставленное слово. Исправлено: sep досылается,
   undo-точка ставится.
3. [P2] gap-BS при пустом gapBuf не синхронизировал buf (обе ветки).
4. [P2] Option+буква в gap-ветке считалась текстом.
5. [P2] ложные страйки (юзер правит BS+ретайп) → затухание 60 с + TTL
   враждебности 10 мин.
6. [P2] settle-бюджет 1,4 с резанут до 0,3 с (риск tapDisabled).
7. [P3] hotkeys мертвы в suppress-окне (комментарий врёт) — задокументировано.
8. [P3] undoLen в паст-флипе не учитывает пробелы выделения — задокументировано.

## Правило на будущее

Каждый батч фиксов проходит аудит субагентом (read-only) ДО доставки —
аудит 05.11 окупился: нашёл «коммит-месседж врал» и 3 бага моих же защит.
Двухплатформенное правило [[commit-push-every-change]]: экран-фиксы mac-only
по природе, но каждый получает вин-эквивалент или записанную причину N/A.
