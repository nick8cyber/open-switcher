# ADR-002: Умный режим детектора — цель с опечаткой 1–2 буквы

Статус: принято 01.11.2026; **обновлено 18.11.2026 и в релизе 1.3.0** (ускорение до $O(L)$, переход на `hasCore`, фикс словарей).

## Обновление 18.11.2026 (аудит лагов и ложных совпадений)

Квадратичный перебор пар произвольных замен (`dist2`, до 130 000 аллокаций строк + `trim`/`lowercased` и проверка по зашумлённому 350k-словарю субтитров `WordDataHuge`) вызывал **зависание потока `CGEventTap` до 573 мс** (системный таймаут macOS отключал тап и терял нажатия) и давал ложные совпадения с мусорными токенами из субтитров (`gemin` и др.).

Итоговый алгоритм `WordDict.dictNeighbor` / `WordDict.DictNeighbor` (< 0.1 мс, macOS + Windows C# 5):
1. Проверка выполняется строго по **чистому ядру словаря** (`hasCore` / `HasCore`: ручное ядро + частотник 35k RU / 20k EN, **без** `WordDataHuge`), без лишних `trim()`/`lowercased()` внутри циклов.
2. `dist = 1` (от 4 букв): 1 замена буквы, 1 пропущенная буква (вставка), 1 лишняя буква (удаление — только от 5 букв).
3. `dist = 2` (от 5 букв): **только смежная транспозиция соседних букв** (`првиет` → `привет`, сложность $O(L)$). Произвольные 2 замены удалены.

## Контекст

Ворота авто-конвертации требовали, чтобы «другое» чтение слова было ТОЧНЫМ
словарным словом. Опечатка в неправильной раскладке выпадала целиком:
бой 17:29 — 'cvjmhb' (хотел «смотри», палец на `m` вместо `n`) читалось
как «смоьри» — не слово (невозможное «оь») → отказ; Option-тапы тоже
отказали (слово уже не последнее и старше 10 с). Юзер оставался с мусором.

## Решение

Если (и только если):
- цель-чтение НЕ словарное слово,
- но существует словарное слово на дистанции ≤2 **замен** букв
  ('смоьри' ≈ 'смотри' — dist1; 'првиет' ≈ 'привет' — dist2: смежная
  транспозиция это ровно 2 замены),
- набранное — «глубокий мусор» своего языка: ∉ словарь И биграммно
  невозможно (possible_word = false),

то цель считается валидной → переворот выполняется, буквы сохраняются
как набраны (опечатку правит юзер; автопоправки НЕТ).

Пороги против ложных срабатываний («погрешности»):
- dist1 — длина ≥ 4, маржа скора 1x;
- dist2 — длина ≥ 6 (для коротких две замены — полслова), ПОЛНАЯ маржа 2x;
- *(в редакции 01.11 допускались только замены; с 18.11 в dist=1 добавлены также
  одиночный пропуск и одиночная лишняя буква — см. раздел выше)*;
- опечатка СВОЕГО языка ('hellp') биграммно возможна → не трогается
  никогда.

Поиск соседа: после аудита `18.11` выполняется за $O(L)$ по `WordDict.hasCore` /
`WordDict.HasCore` (без `WordDataHuge`), а не по полному 350k-слою.

## Следствия (вкл. 1.3.0)

- Вин+мак паритет (C#-версия собирается CI на теге).
- В `1.3.0` исправлено пробельное объединение чанков `WordData` / `WordDataHuge`
  (`" "` вместо слипания слов на стыках) и удалена `repr`-обёртка списка Python в
  Windows `WordDataHuge.cs` — `possibleWord` и `WordDict.Has` больше не теряют
  слова на границах чанков.
- Selftest-дискриминаторы: 'hellp' possible (защищено), 'cvjmhb' — нет
  (разрешено), 'првиет' dist2, 'смотр' (пропуск), 'смоотри' (лишняя буква),
  детерминированный 'пкивед'.
- Не срабатывает: ≥3 опечаток, слова <4 (dist1) и <5–6 (dist2) букв —
  осознанный предел угадывания; для них — Option-тап (живой буфер),
  выделение+тап (задним числом), Break-форс.
- Угаданный «сосед» используется только как РАЗРЕШЕНИЕ на переворот —
  текст замены всегда буквально то, что набрал юзер.
